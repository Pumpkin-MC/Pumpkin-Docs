# RCON（遠端主控台）

## 什麼是 RCON

RCON（遠端主控台）是 Valve 設計的一種協定，允許管理員遠端控制和管理遊戲伺服器。它提供了一種從其他位置（例如手機或另一臺計算機）在伺服器上執行指令的方式。

## 為什麼使用 RCON

- **便利性：** 從任何有網際網路連線的地方管理伺服器。
- **靈活性：** 無需親自位於伺服器所在地即可執行指令。
- **效率：** 自動化任務並簡化伺服器管理。

## SSH 與 RCON

### SSH

- 提供強加密，保護用戶端與伺服器之間傳輸的資料。
- 主要用於安全遠端登入以及在遠端機器上執行指令。
- 通常用於管理 Linux/Unix 系統、設定網路和執行指令碼。
- 提供類似 shell 的環境，允許執行各種指令並與遠端系統互動。

### RCON

- 專為遊戲伺服器的遠端管理而設計，可控制和管理伺服器的設定與執行。
- 安全性通常低於 SSH，因為它往往依賴明文密碼。
- 主要由遊戲伺服器管理員用於管理遊戲伺服器。
- 提供一組有限的遊戲專用指令。

### 封包

RCON 是一種非常簡單的協定，只有少數幾種封包。RCON 封包的結構如下：

| 欄位 | 描述 |
| ----- | --- |
| ID | 用於指示身分驗證失敗或成功 |
| Type | 標識封包型別 |
| Body | 一條訊息（String），例如指令或密碼 |

#### 伺服器接收封包 <sub><sub>（用戶端→伺服器）</sub></sub>

| Type | 封包 |
| ---- | ----------- |
| 2    | Auth |
| 3    | ExecCommand |

#### 用戶端接收封包 <sub><sub>（伺服器→用戶端）</sub></sub>

| Type | 封包 |
| ---- | ------------ |
| 2    | AuthResponse |
| 0    | Output |

### RCON 的工作原理

1. **身分驗證：**

   - RCON 用戶端傳送包含所需密碼的身分驗證封包。
   - 伺服器驗證密碼，並返回身分驗證回應封包。
   - 如果成功，回應封包包含與用戶端所傳送封包相同的 ID；如果失敗，ID 為 -1。

2. **指令執行：**

   - 透過身分驗證的用戶端隨後可以傳送指令執行封包，每個封包包含一條要執行的指令。
   - 伺服器處理指令，併發回包含結果或任何錯誤訊息的輸出封包。

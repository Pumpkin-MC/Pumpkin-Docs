# RCON（远程控制台）

## 什么是 RCON

RCON（远程控制台）是 Valve 设计的一种协议，允许管理员远程控制和管理游戏服务器。它提供了一种从其他位置（例如手机或另一台计算机）在服务器上执行命令的方式。

## 为什么使用 RCON

- **便利：** 从任何有互联网连接的地方管理服务器。
- **灵活：** 无需亲自位于服务器所在地即可执行命令。
- **效率：** 自动化任务并简化服务器管理。

## SSH 与 RCON

### SSH

- 提供强加密，保护客户端与服务器之间传输的数据。
- 主要用于安全远程登录以及在远程机器上执行命令。
- 通常用于管理 Linux/Unix 系统、配置网络和运行脚本。
- 提供类似 shell 的环境，允许执行各种命令并与远程系统交互。

### RCON

- 专为游戏服务器的远程管理而设计，可控制和管理服务器的设置与运行。
- 安全性通常低于 SSH，因为它往往依赖明文密码。
- 主要由游戏服务器管理员用于管理游戏服务器。
- 提供一组有限的游戏专用命令。

### 数据包

RCON 是一种非常简单的协议，只有少数几种数据包。RCON 数据包的结构如下：

| 字段 | 描述 |
| ----- | --- |
| ID | 用于指示身份验证失败或成功 |
| Type | 标识数据包类型 |
| Body | 一条消息（String），例如命令或密码 |

#### 服务器接收数据包 <sub><sub>（客户端→服务器）</sub></sub>

| Type | 数据包 |
| ---- | ----------- |
| 2    | Auth |
| 3    | ExecCommand |

#### 客户端接收数据包 <sub><sub>（服务器→客户端）</sub></sub>

| Type | 数据包 |
| ---- | ------------ |
| 2    | AuthResponse |
| 0    | Output |

### RCON 的工作原理

1. **身份验证：**

   - RCON 客户端发送包含所需密码的身份验证数据包。
   - 服务器验证密码，并返回身份验证响应数据包。
   - 如果成功，响应数据包包含与客户端所发送数据包相同的 ID；如果失败，ID 为 -1。

2. **命令执行：**

   - 通过身份验证的客户端随后可以发送命令执行数据包，每个数据包包含一条要执行的命令。
   - 服务器处理命令，并发回包含结果或任何错误消息的输出数据包。

# 世界引擎与格式

世界引擎主要由 [`pumpkin-world`](https://github.com/Pumpkin-MC/Pumpkin/tree/master/crates/pumpkin-world) crate 管理。它负责世界存储格式、区块读写、地形生成、光照计算和block tick 更新。

---

## 支持的世界格式

Pumpkin 旨在支持多种区域和世界格式，让服务器管理员能够在原版兼容性与现代高性能压缩之间灵活选择。

### 1. Anvil 文件格式（`.mca`）

Anvil 是原版 Minecraft: Java Edition 使用的标准格式。

- **结构**：区块按每区域 32×32 个区块分组，存储在 `.mca` 文件中（`r.{x}.{z}.mca`）。
- **数据层**：每个区块包含方块状态调色板、生物群系调色板、高度图、方块实体和光照数组。
- **压缩**：区域文件中的各个区块使用 ZLib 或 LZ4 压缩。
- **支持情况**：Pumpkin 支持 Anvil 区域文件的**加载和保存**。

### 2. Linear 区域格式（`.linear`）

Linear 是 Anvil 的现代替代方案。它使用 **Zstandard（zstd）** 对整个区域进行压缩，而不是按区块使用 zlib 压缩块，从而大幅减小世界存档体积并加快磁盘 I/O。

- **空间节省**：在主世界和下界可减少约 50% 的磁盘占用，在末地最多可减少约 95%。
- **性能**：解压速度快、磁盘写入量少，非常适合高吞吐量的生产服务器。
- **支持情况**：`pumpkin-world` 内置原生读写支持。

### 3. Slime 世界格式（`.slime`）

Slime 格式最初由 Hypixel 开发，可将整个世界打包成单个紧凑且易于复制的二进制文件。它针对小游戏和临时的实例化世界进行了优化。

### 4. Pump 格式

Pumpkin 的原生区块存储格式，专为快速序列化而设计，没有 Anvil 格式的历史遗留开销。

---

世界引擎将区块管理和 tick 更新组织为多个层级：

### 层次结构

1. **`World`**：管理维度（`overworld`、`the_nether`、`the_end`），协调该维度内的玩家并广播更新。
2. **`Level`**：核心数据结构，保存区块表、高度边界（原版 1.18+ 世界为 -64 到 320）、方块注册表和 tick 调度器。
3. **`Chunker`**：管理视距和玩家订阅。使用 `CylindricalChunkIterator` 计算玩家移动时应向其流式传输哪些区块。

### 异步区块管线

为了保持稳定的 20 TPS tick 速率：

- 在内存缓存中检查玩家请求的区块。
- 未缓存的区块会从磁盘加载，或通过 **Rayon** 后台任务生成，不会使主 tick 循环停顿。
- 已完成的区块通过异步通道分派到玩家的连接流。

## 世界生成管线

当世界尚无已保存的区块，或玩家探索到已生成边界之外时，Pumpkin 会通过包含 6 个阶段的管线生成新区块：

1. **噪声路由器**：多倍频 3D Perlin 和 Simplex 噪声算法计算大陆性、侵蚀度以及山峰/山谷。
2. **密度塑造**：将连续的 3D 噪声值转换为地形密度以及固体与空气体素的阈值。
3. **生物群系气候映射**：对温度、湿度、大陆性和侵蚀度进行采样，以分配生物群系 ID。
4. **表面规则**：评估分层规则，根据暴露程度和海拔放置草方块、泥土、沙子、砂岩或深板岩。
5. **雕刻器**：在坚固岩石中雕刻出 3D 洞穴隧道、峡谷和含水层。
6. **地物与装饰**：放置矿脉、植被、树木、结构和地表植物。

### 1. 噪声路由器与密度函数

Pumpkin 实现了 Minecraft 的多倍频 3D Perlin 和 Simplex 噪声算法：

- 计算大陆性、侵蚀度、山峰与山谷以及 3D 密度。
- 生成自然的地形形状，包括悬垂地形、浮空岛、山地和深洞。

### 2. 生物群系气候参数

生物群系根据多维气候坐标动态确定：

- 温度
- 湿度
- 大陆性
- 侵蚀度
- 深度
- 奇异性

这些参数与原版 Minecraft 的生物群系调色板一致，可生成平滑的生物群系过渡。

### 3. 生成器

- **类原版地形生成器**：完整的 3D 噪声生成，符合现代 Minecraft 的世界高度限制（Y = -64 到 Y = 320）。
- **超平坦生成器**：可配置的平坦地层（例如 Y=-64 处的基岩、泥土，以及顶层的草方块）。

## 光照与 tick 更新

### 1. 光照引擎

- **方块光照**：从发光方块（火把、荧石、熔岩）动态传播，最高为 15 级。
- **天空光照**：从天空向下垂直传播，穿过透明和半透明方块（树叶、水）。
- 系统会计算光照数组并将其序列化到发往客户端的区块数据包中，使客户端能够渲染准确的阴影。

### 2. 方块与区块 tick 更新

- **scheduled tick**：请求延迟执行的方块（水流、下落的沙子、红石中继器）。
- **random tick**：每 tick 从每个子区块中随机选取方块，用于模拟植物生长、冰融化和作物成熟。

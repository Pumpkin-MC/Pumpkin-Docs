# 世界引擎與格式

世界引擎主要由 [`pumpkin-world`](https://github.com/Pumpkin-MC/Pumpkin/tree/master/crates/pumpkin-world) crate 管理。它負責世界儲存格式、區塊讀寫、地形生成、光照計算和方塊 tick 更新。

---

## 支援的世界格式

Pumpkin 旨在支援多種區域和世界格式，讓伺服器管理員能夠在原版相容性與現代高效能壓縮之間靈活選擇。

### 1. Anvil 檔案格式（`.mca`）

Anvil 是原版 Minecraft: Java Edition 使用的標準格式。

- **結構**：區塊按每區域 32×32 個區塊分組，儲存在 `.mca` 檔案中（`r.{x}.{z}.mca`）。
- **資料層**：每個區塊包含方塊狀態調色盤、生物群系調色盤、高度圖、方塊實體和光照數組。
- **壓縮**：區域檔案中的各個區塊使用 ZLib 或 LZ4 壓縮。
- **支援情況**：Pumpkin 支援 Anvil 區域檔案的**載入和儲存**。

### 2. Linear 區域格式（`.linear`）

Linear 是 Anvil 的現代替代方案。它使用 **Zstandard（zstd）** 對整個區域進行壓縮，而不是按區塊使用 zlib 壓縮塊，從而大幅減小世界存檔體積並加快磁碟 I/O。

- **空間節省**：在主世界和地獄可減少約 50% 的磁碟佔用，在終界最多可減少約 95%。
- **效能**：解壓速度快、磁碟寫入量少，非常適合高吞吐量的生產伺服器。
- **支援情況**：`pumpkin-world` 內建原生讀寫支援。

### 3. Slime 世界格式（`.slime`）

Slime 格式最初由 Hypixel 開發，可將整個世界打包成單個緊湊且易於複製的二進制檔案。它針對小遊戲和臨時的實例化世界進行了優化。

### 4. Pump 格式

Pumpkin 的原生區塊儲存格式，專為快速序列化而設計，沒有 Anvil 格式的歷史遺留開銷。

---

世界引擎將區塊管理和 tick 更新組織為多個層級：

### 層次結構

1. **`World`**：管理維度（`overworld`、`the_nether`、`the_end`），協調該維度內的玩家並廣播更新。
2. **`Level`**：核心資料結構，儲存區塊表、高度邊界（原版 1.18+ 世界為 -64 到 320）、方塊註冊表和 tick 排程器。
3. **`Chunker`**：管理視距和玩家訂閱。使用 `CylindricalChunkIterator` 計算玩家移動時應向其流式傳輸哪些區塊。

### 非同步區塊管線

為了保持穩定的 20 TPS tick 速率：

- 在記憶體快取中檢查玩家請求的區塊。
- 未快取的區塊會從磁碟載入，或透過 **Rayon** 後臺任務生成，不會使主 tick 迴圈停頓。
- 已完成的區塊透過非同步通道分派到玩家的連線流。

## 世界生成管線

當世界尚無已儲存的區塊，或玩家探索到已生成邊界之外時，Pumpkin 會透過包含 6 個階段的管線生成新區塊：

1. **噪聲路由器**：多倍頻 3D Perlin 和 Simplex 噪聲演算法計算大陸性、侵蝕度以及山峰/山谷。
2. **密度塑造**：將連續的 3D 噪聲值轉換為地形密度以及固體與空氣體素的閾值。
3. **生物群系氣候對映**：對溫度、溼度、大陸性和侵蝕度進行取樣，以分配生物群系 ID。
4. **表面規則**：評估分層規則，根據暴露程度和海拔放置草方塊、泥土、沙子、砂岩或深板岩。
5. **雕刻器**：在堅固岩石中雕刻出 3D 洞穴隧道、峽谷和含水層。
6. **地物與裝飾**：放置礦脈、植被、樹木、結構和地表植物。

### 1. 噪聲路由器與密度函數

Pumpkin 實現了 Minecraft 的多倍頻 3D Perlin 和 Simplex 噪聲演算法：

- 計算大陸性、侵蝕度、山峰與山谷以及 3D 密度。
- 生成自然的地形形狀，包括懸垂地形、浮空島、山地和深洞。

### 2. 生物群系氣候參數

生物群系根據多維氣候座標動態確定：

- 溫度
- 溼度
- 大陸性
- 侵蝕度
- 深度
- 奇異性

這些參數與原版 Minecraft 的生物群系調色盤一致，可生成平滑的生物群系過渡。

### 3. 生成器

- **類原版地形生成器**：完整的 3D 噪聲生成，符合現代 Minecraft 的世界高度限制（Y = -64 到 Y = 320）。
- **超平坦生成器**：可設定的平坦地層（例如 Y=-64 處的基岩、泥土，以及頂層的草方塊）。

## 光照與 tick 更新

### 1. 光照引擎

- **方塊光照**：從發光方塊（火把、熒石、熔岩）動態傳播，最高為 15 級。
- **天空光照**：從天空向下垂直傳播，穿過透明和半透明方塊（樹葉、水）。
- 系統會計算光照數組並將其序列化到發往客戶端的區塊封包中，使客戶端能夠渲染準確的陰影。

### 2. 方塊與區塊 tick 更新

- **scheduled tick**：請求延遲執行的方塊（水流、下落的沙子、紅石中繼器）。
- **random tick**：每 tick 從每個子區塊中隨機選取方塊，用於模擬植物生長、冰融化和作物成熟。
